# [PROJECT NAME] -- Master Plan v1

> **What this document is:** the "what and why." Scope, model, phases, open
> questions. When the definition of the project changes, you REWRITE this as v2,
> v3 -- you don't patch it. Delete these prompt lines as you fill each section.

## 1. Scope
> One paragraph: what is being built, and what is explicitly NOT in scope.
> If there's a pilot vs. product distinction, state it here.

## 2. Why it exists
> The problem. Who has it. Why existing options don't solve it.

## 3. Jobs to be done (ranked)
> What the thing must do, ranked, each marked must-have or nice-to-have.

## 4. Non-negotiables
> The constraints that don't move. Cost ceiling, who must be able to use it,
> data/ownership rules, anything that would kill the project if violated.

## 5. Stack / approach (decided)
> The chosen tools/methods and the one-line rationale for each. Mark anything
> still under evaluation as OPEN.

## 6. Phases
> Numbered. Each phase should fund/prove the next. Note rough cost and time.

## 7. Business / outcome model
> How it sustains itself, or what success looks like if it isn't a business.

## 8. Open questions queue
> The live list. Move items out as they close. This is never empty on a real
> project -- if it looks empty, you're not looking hard enough.
